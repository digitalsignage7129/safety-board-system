# 安全掲示板システム

顧客ごとに内容を編集できる「安全＋掲示板」を、Webページとして配信するための小さなシステムです。
led-cloud.com経由でSTB(Magic player)にWebページを表示する運用を想定しています。

## できること

- 現場(顧客)ごとに **表示用URL** と **編集用URL** の2つのリンクを発行します。
  - 表示用URL(`board?id=…`): led-cloud.comの「Webページ」コンテンツとして登録し、STBに表示させます。閲覧専用で、誰でも(ログイン不要で)開けます。
  - 編集用URL(`board?id=…&key=…`): 顧客に渡すリンクです。ログイン不要で、このURLを知っている人だけが内容を編集できます。
- 玉掛けワイヤーロープの点検色を4色分設定すると、**4ヶ月周期で自動的に切り替わり**、以降もずっと繰り返されます。画面には該当する月の色のみを表示し(4色すべてを並べて枠で囲む表示はしません)、すっきり見せています。
- 「無災害記録」の欄では、稼働時間の記録(目標時間・何月何日現在で何時間か)と工期(開始日~終了日)を表示できます(任意項目。目標時間・現在の時間の両方が0の場合は欄自体が表示されません。稼働時間は自動加算されないため、更新するたびに数値と基準日を入力し直してください)。件数の少ない・多いにかかわらず見やすいよう、数字は大きな桁ごとの枠で表示されます。
- 緊急時連絡先の欄を用意しています。現場代理人・電気・水道・ガス・警察・消防・病院など、よくある項目をあらかじめ用意しているので、担当者名と電話番号を入力するだけで使えます。項目名の変更・追加・削除も可能です(最大12件)。登録した件数に応じて1件あたりの文字・行の大きさが自動的に調整されるため、件数が少ないときに欄の下側が余ったり、多いときにはみ出したりしません。
- 今月の安全目標・お知らせ・自由記入欄(見出し+本文を好きな数だけ追加可能)は、顧客側で自由に文字を入力できます。
- 「玉掛けワイヤーロープの点検表」「安全施工サイクル」「3・3・3運動」は、管理画面から1回画像をアップロードすればすべての現場で共通して表示されます。
- 「当作業所のクレーン等の合図法」は現場ごとに内容が異なることが多いため、現場ごとに画像を差し替えられるようになっています(未設定の場合は共通の既定画像が表示されます)。
- デザインは、白地に青いグラデーションの見出しバナー・黄色の差し色・極太ゴシック体(見出しや数字)を使った、現場でよく見る安全掲示板に近い配色・書体にしています。フォントは外部サービス(Google Fonts等)を使わず、`public/fonts/` にファイルを同梱しているため、閲覧側のネットワーク環境に左右されず安定して表示されます。
- **表示レイアウトを「すべて表示」「4分割」「2分割」「1つだけ表示」から選べます**。サイネージの実寸(75インチ~200インチ)やドットピッチ(2.8mm/3.3mmなど)によっては、一度に全項目を表示すると文字が小さくなりすぎて読めなくなるため、設置するディスプレイに合わせて画面に表示する項目数を絞り込み、残りの項目はより大きな文字で表示できるようにしています。この設定は管理画面(admin.html)から現場ごとに行います(顧客の編集用URLには影響しません)。

## 表示レイアウトの選び方(管理画面)

管理画面の現場一覧から「表示レイアウト」ボタンを押すと、現場ごとに以下を設定できます。

- **すべて表示**: 全項目を一度に表示します(既存のデザイン)。125インチ以上など、比較的大きく高精細なディスプレイ向けです。
- **4分割**: 画面を4つに分け、指定した4項目を大きく表示します。
- **2分割**: 画面を2つに分け、指定した2項目をさらに大きく表示します。
- **1つだけ表示**: 指定した1項目のみを画面いっぱいに表示します。75インチ前後・ピッチが粗いディスプレイなど、文字を大きくしたい場合に適しています。

「設置ディスプレイのメモ」欄は表示には影響しない備考欄です。設置したディスプレイのサイズ・ピッチを記録しておくためにご利用ください。

## 構成

このリポジトリは、**2通りの動かし方**に対応しています(中身のロジックはほぼ同じで、データの保存先だけが違います)。

- **Cloudflare Pages版(推奨)**: GitHubにpushするだけでCloudflareが自動的にビルド・公開してくれる構成。サーバーの契約・維持が不要です。
  - `functions/` … Cloudflare Pages Functions(APIの実体。`server.js`と同じ処理をD1・R2向けに書き直したもの)。
  - `functions/_lib/db.js` … ボードの読み書き・点検色の計算など、共通ロジック。
  - `migrations/0001_init.sql` … D1(データベース)の初期スキーマ。
  - `wrangler.toml` … ローカル動作確認(`wrangler pages dev`)用の設定。本番のバインディングはCloudflareダッシュボード側で設定します(下記手順を参照)。
- **Node.js版(従来どおり)**: 自前のサーバー・VPSやRender/RailwayなどのPaaSで動かす構成。
  - `server.js` … Node.js(Express)によるサーバー。データは`data/boards/*.json`という単純なファイルに保存します。
  - `data/` … 実行時に作成されるデータ保存先(現場ごとのJSON、アップロード画像)。

どちらの構成でも、画面(顧客が見る/編集する部分)は共通です。

- `public/board.html`, `board.js`, `board.css` … 表示/編集ページ本体。
- `public/admin.html`, `admin.js` … 管理画面(現場の追加・URL発行・共通画像の管理)。

## Cloudflareで公開する手順(推奨)

GitHub・Cloudflare・cron-job.orgを使って公開する場合の手順です。サーバーの契約・維持や証明書の更新が不要で、GitHubにpushするたびに自動的に反映されます。

### 1. GitHubにリポジトリを作成してpushする

このフォルダの中身をそのままGitHubリポジトリにpushしてください(`node_modules/`は`.gitignore`で除外済みです)。

### 2. Cloudflareでデータベース(D1)とファイル保存先(R2)を作る

Cloudflareダッシュボードにログインし、以下を作成します(それぞれ数クリックで作れます)。

- **D1データベース**: 「Workers & Pages」→「D1 SQL Database」→「作成」。名前は何でも構いません(例: `safety-board-db`)。
- **R2バケット**: 「R2」→「バケットを作成」。名前は何でも構いません(例: `safety-board-assets`)。R2は月10GBまで無料で使えます。

### 3. Pagesプロジェクトを作り、GitHubと連携する

「Workers & Pages」→「作成」→「Pages」→「Gitに接続」から、先ほどのリポジトリを選択します。

- フレームワークプリセット: **なし(None)**
- ビルドコマンド: **空欄のまま**
- ビルド出力ディレクトリ: **`public`**

これで保存すると、最初のデプロイが始まります(この時点ではまだD1・R2につながっていないため、APIはまだ動きません)。

### 4. D1・R2をPagesプロジェクトに紐づける(バインディング)

デプロイができたら、そのPagesプロジェクトの「設定」→「Functions」を開き、以下を追加します(名前は大文字・小文字も含めて正確に合わせてください)。

- **D1データベースのバインディング**: 変数名 `DB` → 手順2で作ったデータベースを選択
- **R2バケットのバインディング**: 変数名 `BOARD_BUCKET` → 手順2で作ったバケットを選択
- **環境変数**: `ADMIN_PASSWORD` に管理画面用のパスワードを設定(「暗号化する」を選択推奨)

設定を保存したら、「デプロイメント」タブから最新のデプロイを「再試行(Retry deployment)」して、バインディングを反映させてください。

### 5. データベースの初期化(テーブル作成)

手元のパソコンでこのリポジトリをcloneし、以下を実行します(初回のみ)。

```bash
npm install -g wrangler
wrangler login
wrangler d1 execute safety-board-db --remote --file=./migrations/0001_init.sql
```

(`safety-board-db` は手順2で付けたデータベース名に置き換えてください)

### 6. 動作確認

`https://(プロジェクト名).pages.dev/admin` を開き、手順4で設定したパスワードでログインできれば完了です。「新しい現場を追加」から現場を作成し、表示用URL・編集用URLが発行されることを確認してください。

### 7. 独自ドメインをつける(任意)

すでにCloudflareで管理しているドメインがあれば、Pagesプロジェクトの「カスタムドメイン」から数クリックで割り当てられます(無料のSSL証明書も自動で発行されます)。

### 8. cron-job.orgで死活監視する(任意)

Cloudflare Pagesは常時起動のサーバーではないため、Render等の無料プランのような「スリープ防止」のpingは不要です。代わりに、**サイトが落ちていないかの見張り役**としてcron-job.orgを使うのがおすすめです。

- cron-job.orgで新しいジョブを作成し、URLに `https://(あなたのドメイン)/api/health` を設定
- 実行間隔: 5~15分程度
- 「失敗時にメール通知」を有効にする

これで、万一データベース接続などに問題が起きた場合にメールで気づけます。

### ローカルでの動作確認(任意)

```bash
npm install -g wrangler
wrangler d1 execute safety-board-db --local --file=./migrations/0001_init.sql
wrangler pages dev public
```

`http://localhost:8788/admin` で確認できます(ローカルではD1・R2の中身はパソコン内に保存され、本番のデータとは別物です)。

## Node.jsで公開する場合(従来どおりの方法)

サーバー・VPSを自分で用意できる場合や、Render/RailwayなどのPaaSに慣れている場合は、こちらの方法でも公開できます。

Node.js 18以降が必要です。

```bash
npm install
ADMIN_PASSWORD=好きなパスワード npm start
```

起動後、ブラウザで `http://localhost:3000/admin` を開き、表示されたパスワードでログインしてください。
「新しい現場を追加」から現場名を入力すると、表示用URL・編集用URLがすぐに発行されます。

STB(led-cloud.com)や顧客はこのサーバーに**インターネット経由でアクセスできる必要があります**。そのため、どこかのサーバー/ホスティングサービスに公開する必要があります。

代表的な方法:

1. **お手持ちのサーバー・VPSで動かす**: `npm install && ADMIN_PASSWORD=... PORT=3000 npm start` を実行し、常時起動させます(`pm2` や `systemd` などで自動再起動する設定を推奨します)。独自ドメイン+HTTPS(Let's Encrypt等)を設定すると、URLが短く・安全になります。
2. **Render / Railway などのPaaSにデプロイする**: このフォルダをGitリポジトリにして接続するだけで、Node.jsアプリとして自動的に公開できます。環境変数 `ADMIN_PASSWORD` を管理画面で設定してください。無料枠は一定時間アクセスがないと休止する場合があるため、常時表示するサイネージ用途では有料プランの利用を推奨するか、cron-job.orgなどで定期的にアクセスしてスリープを防止してください。
3. 画像アップロードは `data/uploads` ディレクトリにファイルとして保存されます。PaaSによっては再起動でファイルが消える(永続ディスクでない)場合があるため、その場合は「永続ボリューム」の追加が必要です。

いずれの場合も、**`ADMIN_PASSWORD` は必ずデフォルト値から変更**してください(管理画面には現場一覧の編集用URL・編集キーが表示されるため)。

## led-cloud.com側の設定について

- 表示用URL(`.../board?id=xxxxxxxx`)を、led-cloud.comの「Webページ」コンテンツとして登録してください(今回のヒアリングで、WebページのURLを指定できるとのことでした)。
- 玉掛けロープの点検色は月が変わったタイミングで自動更新されます。ページ自体も5分ごとに最新の内容を再取得するようにしていますが、**led-cloud.com/STB側で定期的にページを再読み込みする設定になっているか、念のためご確認ください**(常時表示しっぱなしで再読み込みされない設定だと、月が変わっても表示が古いままになる可能性があります)。
- 画面は16:9を基準にデザインしていますが、実際のSTB/ディスプレイの解像度で一度表示を確認し、文字サイズ等の調整が必要であればご連絡ください。

## Claudeのアーティファクト機能ではなくこの形で納品した理由

当初はClaude上で完結するWebページ(URLひとつで顧客編集・STB表示ができるもの)も検討しましたが、Claudeのアーティファクトのデータ保存機能は「同じ組織にサインインしている人だけがアクセスできる」という制限があり、顧客やSTB(サインインできない機器)がアクセスすることができません。そのため、御社で自由にホスティングできるNode.jsアプリとして今回のシステムをお渡ししています。

## セキュリティに関する補足

- 編集用URLに含まれる「key」が実質的なパスワードの役割を果たしています。顧客へは信頼できる方法(メール等)でお渡しください。
- 管理画面(admin.html)はパスワードで保護されていますが、簡易的な仕組みです。社外に管理画面のURLが漏れないようご注意ください。
- 必要に応じて、サーバーの手前にBasic認証やIP制限を追加することも可能です。
